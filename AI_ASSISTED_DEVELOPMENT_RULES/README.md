# AI 辅助开发规则

> **用途声明：** 本目录仅用于 AI 辅助软件开发、代码审查、测试与交付管理，不属于软件业务源码或运行时功能。项目构建与打包流程应排除本目录，除非项目明确要求将其作为文档制品发布。

## 权威来源与适用范围
本目录是供 AI 在 GitHub 仓库中读取和执行的开发规则副本。ChatGPT「软件开发」项目源文件中的主规则是维护规则的权威来源；仓库中的本目录用于让规则随代码变更接受审查、追溯和同步。两者不一致时，先比较差异并报告，不得盲目覆盖仓库中已有的有效修改。

## 强制读取流程
每次开始新开发、继续开发、修复缺陷、全面审查、执行阶段任务、准备合并或准备发布前，AI 必须：
1. 读取本 README 和所有与任务相关的规则文件。
2. 检查项目主规则是否有更新，以及本目录是否缺文件或存在本地修改。
3. 检查仓库、默认分支、当前分支、最新提交、工作区状态、开放 PR、CI 和待办。
4. 按规则执行，并在交付报告中说明读取状态、执行结果、例外和未验证项。

仅仅看到目录存在，不等于已经读取或执行规则。无法读取时必须明确报告，不能假称已遵守。

## 首次接入与同步
- **新建空仓库首次初始化：** 在仓库已存在且写入权限可用时，AI 可将项目文件和本目录一次性上传并直接提交到默认分支；不需要为初始化规则文件专门创建开发分支。
- **已有仓库首次接入：** 先检查现有文件和分支保护。遵循仓库既有治理要求，不得绕过保护或覆盖有效文件。
- **后续开发：** 每个仓库只需初始化一次。每次开发读取现有规则；只有规则发生变化或文件缺失时才同步。
- **同步规则：** 先比较差异，再做最小修改，保留仓库中的有效补充。任何规则同步都必须留下可追溯提交。
- **权限限制：** 若 AI 无法访问、写入或提交仓库，应准确说明缺少的权限或工具能力；不得声称已上传。

## 文件清单
- `DEVELOPMENT_RULES.md`：需求分析、架构、代码修改、Git 分支、PR、CI、发布和交付规则。
- `TESTING_AND_ACCEPTANCE.md`：自动化测试、真实使用测试提醒和验收标准。
- `SECURITY_AND_AUTHORIZATION.md`：安全、隐私、授权、数据保护和恢复要求。
- `CHANGELOG.md`：规则文件变更记录。

## 项目规则与仓库规则
项目设置规定 AI 每次开始工作必须读取本目录；本目录提供可审查的详细规则。CI、分支保护和权限控制用于降低违规风险，但不能单独证明 AI 已读取全部规则。AI 必须如实报告实际执行情况。

## 文件安全
上传前检查密钥、令牌、口令、`.env`、个人敏感信息、缓存、生成产物和不应提交的本地文件。规则文档不得存放真实凭证。不得因为本目录属于 AI 规则，就将它打进应用运行时包或将其中内容当作业务逻辑。
