# LunaTOC-SC 当前技术决策

此文件仅记录本仓库现行设计，不作为原项目的历史决策日志。

## D1 — 单平台 Chrome 扩展

产品仅支持 ChatGPT 的 `chatgpt.com` 与 `chat.openai.com`。使用 Manifest V3、Vite、CRXJS 和 TypeScript。平台抽象保留为宿主 API 与 DOM 的边界，但不注册未实现的平台。

## D2 — 独立虚拟导航

目录定位依赖消息身份与当前挂载 DOM。精确 ID 匹配优先；文本回退仅用于无附件、内容唯一的提问，无法确定时报告失败。虚拟滚动通过有取消条件的视口逐步寻找目标，不调用废弃的原生目录导航策略。

## D3 — 不修改宿主响应式 API

不拦截或伪装 `window.matchMedia`。ChatGPT 的响应式布局由浏览器和网页决定。窄窗口、分屏与固定侧边栏需要真实浏览器回归测试。

## D4 — 活动分支刷新与竞态隔离

侧边栏展开时通过 ChatGPT 同源接口主动刷新。存在映射节点时按 `current_node` 追溯活动分支；否则必须完整获取分页数据，且每个活动节点都有明确父链，才允许替换目录。没有父链的扁平历史记录无法证明是否包含旧编辑分支；这类结果返回“未验证”，保留原目录而非猜测成功。页面原有 `fetch` 请求带起始时间，权威快照应用后禁止新旧非权威分页将其他分支消息合并入已核验目录；已由页面明确观察到的新用户提问仍可追加。

## D5 — 用户提示词数据完整性

保留既有 Chrome 本地存储键，以维持用户数据兼容。存储层返回对象副本，失败写入恢复原缓存，同一扩展上下文内通过队列串行化读—修改—写操作。跨标签页的同时写入不提供事务保证，属于明确的使用边界。

## D6 — 隐私与最小权限

`manifest.json` 仅申请 `storage` 权限并限定 ChatGPT 域名。对话信息用于本地目录和导航；扩展可以向 ChatGPT 同源会话 API 取回当前会话数据，不向维护者服务器传输对话或添加遥测服务。详细说明见 [PRIVACY.md](../PRIVACY.md)。

## D8 — 用户可选布局与本地背景配色

设置页提供并排与浮层两种模式。并排模式默认固定展开，仅对 ChatGPT 实际聊天主容器或带有共同顶部栏的聊天列预留侧边栏宽度；保留原生导航与媒体查询。浮层模式默认隐藏，两个模式均允许随后手动固定切换。侧边栏背景配色采用 ChatGPT 风格预设色板，不写入或反向读取 ChatGPT 的个人设置；默认背景与顶部栏使用原有浅蓝/深蓝半透明主题色并保留背景模糊，其他颜色按当前深浅主题混色。隐藏触发区在完全透明和所选色系半透明之间可选。右侧快捷工具默认收起，首次触碰右缘仅展开侧边栏，之后离开并重新进入右缘、停留 50ms 才按指针高度显示工具；不再支持拖动，键盘入口为侧边栏内的 `Alt+Shift+J`。

## D9 — 目录右键菜单操作

右键菜单以「复制文字、添加tips、编辑文字」开始；当前回答的展开标题存在时始终提供「收起目录」；只有问题目录行或展开标题超出侧边栏无遮挡可视范围时才在前后提供「回到顶部、回到底部」，存在本地别名时另提供「恢复原文」。复制和添加使用 ChatGPT 原始消息内容，添加继续打开提示词保存弹窗。回到顶部／底部仅操作扩展侧边栏的目录滚动容器 `#navigator-list`，在毛玻璃顶栏下方完整展示被选中目录行，或在底部完整展示后续第一条可见目录项（没有后续项则对齐当前回答最后一个标题），不影响 ChatGPT 对话正文；收起或整段已展开目录均完整可见时不显示操作，即使菜单开启后目录重新变为完整可见也会拒绝多余滚动。保留虚拟列表查找、原始消息身份、搜索状态和正常左键的标题展开行为。收藏功能、收藏导致的目录高亮以及跨回答保持展开的逻辑彻底删除，因为确认不存在需要迁移的历史收藏数据。

## D11 — 本地目录文字与右缘动态按钮

目录文字重命名仅是按永久会话 ID、消息 ID 存储在 Chrome 本地存储的显示别名；右键第三项在当前行显示高度自适应的多行文本区，随换行和宽度变化显示完整文字；Enter 提交、Shift+Enter 换行、Esc 取消、失焦提交，写入失败保留原位编辑和草稿；目录跳转、复制和提示词添加继续使用 ChatGPT 原始内容。目录右键「编辑文字」直接原位编辑，已有别名时提供「恢复原文」；对临时路由不允许持久重命名；搜索可匹配别名或原文。别名参加 D10 的会话启动校验与删除联动，未知账号及网络失败不执行自动删除。三个导航按钮不使用固定底部坐标、拖动或存储位置；首次鼠标触边仅展开侧边栏；离开右缘后再次进入且持续停留 50ms 才在当前指针高度显示工具组，边缘退出会取消计时；点击期间保持位置，并裁切至视口内。

## D12 — 回答目录三级与缺级压缩

回答目录最多使用当前回答中实际存在的三个标题级别，按原生 H1–H6 从浅到深选择；缺少的中间等级不产生空父节点，其余等级压缩为 1–3 级显示。保留 DOM 出现顺序以及原生 headingLevel + text + occurrence 描述符以确保重复标题仍可精确跳转。第四种及之后更深的标题级别不纳入目录。

## D7 — 测试与发布

所有功能变更添加 Vitest 回归用例。CI 对 PR 与主分支执行类型检查、单元测试、构建、Manifest 资源检查及 ZIP 验证；仅通过 main 上手动确认的发布工作流发布预览包；PR 和 main 推送均不自动发布。CI 只授予仓库读取权限，发布写权限仅授予发布作业；不自动清理旧 Release、标签或开发分支。同一标签不可覆盖。回退通过已保留的 Release/标签进行。涉及 ChatGPT 页面结构的更改必须另行进行手动浏览器验收。

## D10 — 会话生命周期以 ChatGPT 为准

在每次打开或刷新 ChatGPT 页面时仅识别一次当前登录账号，不启用后台轮询。当前页明确成功的删除操作即时清理对应导航缓存与目录别名；归档不触发清理。由于单数/复数会话接口兼容性和权限差异，单个 GET 的 404/410 不能证明会话已删除，跨设备删除尚不自动回收别名。无归属记录、网络错误、未登录和无法判定状态保留本地数据。活动分支之外的消息不能因缺席当前目录而被认定删除。扩展维护的导航快照有容量上限和显式删除接口；获取权威快照失败时保留旧数据但标记未验证。独立保存的「我的提示词」不随聊天删除；其使用统计以现存提示词 ID 为准执行本地核对。

## D13 — 维护期保守回收、异步一致性与界面回归

单次会话存在性请求失败不能触发本地别名删除；启动请求只核对当前账号身份，观察到页面内成功删除操作才能清理。单扩展上下文内的别名写入与删除排队，删除标记阻止晚到写入重新创建本地记录；跨标签页没有 Chrome 存储 CAS 事务，需后续独立机制解决。刷新超时或失败不视为已验证；右键菜单使用真实高度定位并限制滚动区域，隐藏标题不计入三级提取，已连接但内容更改的标题失效后重新提取。旧主题键在迁移完成后清理。侧边栏内 Alt+Shift+J 为隐藏导航按钮提供键盘入口。

## D14 — 侧边栏隐藏滚动轨道与触边 50ms 延迟

目录列表仅隐藏可见滚动轨道，不禁用实际滚动；保留 `overflow-y: auto`、鼠标滚轮、触控板、触屏及代码定位。使用标准 `scrollbar-width: none` 和 WebKit 伪元素兼容实现。工具组仍需先离开首次触边的右侧区域，再次进入并连续停留 50ms 后才显示；离开右缘或关闭侧边栏会取消计时。

## D15 — 已展开标题目录的局部边界导航

右键「回到顶部／回到底部」仅用于过长的已展开回答标题列表，且仅滚动扩展的 `#navigator-list`，顶部对齐被选中目录行且避开顶部毛玻璃栏；底部优先完整露出下一条可见目录项，没有下一项时对齐当前回答的末个标题。未展开或无标题时隐藏这两项；菜单打开后如展开状态改变、会话切换或行被重绘，动作重新验证当前 DOM 和消息身份，不触发 ChatGPT 正文跳转。右缘全局快捷工具仍是独立功能，再次触边停留时间改为 50ms。

## D16 — 目录边界的可视安全区与悬浮工具延时收起

目录「回到顶部」取 `#navigator-list` 可见起点和 `.navigator-topbar` 实际底边的较大值作为安全边界，保证被选中目录行整体位于毛玻璃顶栏下方；「回到底部」先寻找过滤后仍挂载的下一条目录，并对齐其底边，只有不存在下一条时才对齐展开标题列表最后一项。鼠标进入右缘出现工具组的延迟保持 50ms；鼠标离开已出现的工具组或右缘后等待 400ms 再隐藏，返回立即取消。普通侧边栏自动隐藏仍维持 60ms；仅已显示按钮时离开整个侧边栏采用同样的 400ms 宽限。

## D17 — 展开目录仅在实际溢出时提供边界操作

右键菜单按 `#navigator-list` 的实际 DOM 可视范围计算：被选问题行的文本顶部和展开回答标题列表的底部均不受毛玻璃顶栏与列表下边界遮挡时，不显示「回到顶部／回到底部」；有任意遮挡或溢出才显示。尺寸尚不可测时保留操作避免误隐藏；执行前再次检查以防菜单开启后位置变化。右缘导航工具组的首次显示延迟保持 50ms，已显示后离开等待 400ms 再隐藏，返回取消计时。

## D18 — 展开目录右键直接收起

只要当前问题的回答标题目录已展开且有标题，右键菜单就显示「收起目录」，不依赖滚动溢出；只有确实遮挡时才同时展示「回到顶部 → 收起目录 → 回到底部」。收起调用 `outline.ts` 的按索引状态更新，保留已缓存标题，不触发 ChatGPT 消息导航；触发前校验消息身份、目录行实例和实时展开状态，避免过期菜单误操作。收起时若当前问题目录处于侧边栏顶部无遮挡可视范围之上，在标题 DOM 收起后重新测量位置，将该目录对齐到列表可见顶部；如果目录仍可见则保持当前滚动位置，不改变目录顺序或 ChatGPT 正文位置。

## D19 — 保守的浏览器工具栏兼容性告警

为普通用户始终启用被动契约异常上报，不改变仅供开发者启用的深度探测开关。连续无法收到 MAIN-world 健康握手、以及在既有会话已渲染真实消息的情况下持续缺少关键 DOM 标记，均触发当前标签页的 Chrome action 徽标 `!` 与 popup 升级提醒。状态放在 `chrome.storage.session`，页面重新加载清理旧告警，避免跨标签页污染。不给扩展增加宿主网络探测、遥测、tabs 权限或对话内容传输；未来完全不可观测的站点改版无法得到绝对保证。

## D20 — 本地用户数据的版本化备份与保守恢复

在设置页提供仅本地处理的版本化 JSON 备份，覆盖提示词及使用统计、目录别名、主题和侧边栏设置；旧 Markdown 提示词导入导出不变。不备份 ChatGPT 对话正文、凭证或未知键。导入先进行大小、结构、ID、账号归属校验和预览，再由用户明确选择同 ID 备份优先的合并或覆盖；写入失败尝试按快照回滚。Chrome 存储跨上下文不提供原子事务，因此仍需独立备份并在恢复时避免并发修改。详见 [本地备份与恢复](LOCAL_BACKUP.md)。

## D21 — 提示词跨标签页条件写入

保留 `lumaToc:myPromptsV1` 存储键。新版本 ChatGPT 标签页不直接写提示词集合，而通过 `chrome.runtime.sendMessage` 将旧快照和候选集合交给 Manifest V3 service worker；后台在单队列中验证、读取、比较与写入。冲突时只在前台对最新值重新执行受控转换（最多 8 次），过期编辑、删除和清空在操作层阻止无提示覆盖，后台冲突重试时也会核对受影响的记录 ID，重叠修改直接失败而不同记录可合并；错误存储、后台失联和写入失败均拒绝虚假成功。不自动重试通信失败，避免确认状态未知时重复新增。整表替换必须提供 `getAll()` 返回的原始数组引用，以其读取时快照作为前置条件，不允许来源不明的数据覆盖。内存队列可由服务工作线程重建，持久数据是唯一事实来源。本机制并非 Chrome storage 自带 CAS：备份恢复和旧版扩展直接写入仍需另行协调。失败可回退新代码并保留旧存储键，详见 [数据备份与恢复](LOCAL_BACKUP.md)。

## D22 — 目录别名的跨标签页条件写入与删除隔离

保留旧别名键 `chatToc:aliases:v1:*` 与原有展示格式，不迁移或清理用户数据。编辑器在打开时捕获该消息的别名基准（包含“没有别名”的状态）；提交经扩展后台 `tocAliasWriteCoordinator.ts` 的单队列重新读取持久数据，只比较本次修改的消息条目，不同消息的并发编辑可合并，同一消息的过期编辑与恢复原文拒绝无提示覆盖。已确认删除的会话先在 `chatToc:aliases:deleted:v1:*` 写入持久标记再移除旧别名，防止后台重启、其他标签页的滞后写入重新创建；存储删除失败时保留标记，阻止旧页继续修改。只有用户明确执行备份恢复，才按备份列明的会话移除对应删除标记并在失败时尝试回滚。旧版扩展、备份恢复或其他直接存储写入者不受此后台条件写入协议约束；真实 Chrome 环境尚待独立浏览器自动化阶段验证。


## D23 — 第六阶段历史分支与导航身份保守校验

页面钩子读取完整 mapping 或带有连续 `parent` / `parent_id` 的分页历史，在确认 `current_node` 向根节点可达且无循环、缺失或冲突后，只发送被选中的活动链，并附内部字段 `activeBranchVerified: true`。ISOLATED world 接收端只将通过这一路径校验的结果视为权威快照；无充分证据时保留旧目录并将快照完整性标为 false。经过确认的活动分支不再和后续普通分页混合，避免旧编辑版本复活；需要发现新的分支时重新触发同源主动刷新。用户提交事件继续直接加入当前活动目录。目录跳转优先精确消息 ID，文本回退只允许全量规范化内容相等且唯一的纯文本提问，绝不以前缀猜测。路由或分支更新时取消上一个跳转的异步定位。以上机制只保证代码路径的可证明性，不承诺 ChatGPT 在所有版本都提供足够的父节点信息；未确认时宁可保留旧目录，真实网页自动化验收安排于后续阶段。


## D24 — 兼容性警告的有证据恢复

浏览器工具栏告警不受开发者弹窗关闭操作影响，只有页面路由改变（先清空再重新检测）或得到契约正常工作的明确证据时才清除。内容脚本使用单调递增修订号上报异常和恢复；后台串行处理同一标签页消息，在会话存储保留健康状态修订号，防止过期异常在恢复后重新亮起。对已渲染对话关键 DOM 标记使用连续两次健康采样，MAIN-world 页面钩子使用 PING/PONG 和已检查接口请求的正向匹配；空页面、未加载的对话和网络探测失败不当作恢复证据。所有标记仅临时存储于 `chrome.storage.session`，不加入遥测或额外站点权限。自动化测试验证逻辑，但真实 ChatGPT 页面行为仍需后续浏览器验收阶段核实。


## D25 — 目录高亮的常数级 DOM 更新与合成基准

第八阶段在 100、500、2,000 条合成目录数据上测量首次渲染、复用渲染、搜索与连续高亮切换；单次 GitHub Actions runner 时间是诊断指标，不将毫秒数直接作为 CI 阈值或真实 Chrome 性能声明。针对已确认的滚动高频路径，`tocListRenderer.ts` 只维护前后两个高亮 DOM 行，重绘、过滤、行替换与重置时同步修正引用；以每次高亮切换至多移除一个高亮类作为确定性的回归门槛。保留其他尚未证实的性能路径，不做大规模虚拟化改造。`num_turns=100` 的 ChatGPT 请求改写不根据 jsdom 数字调整，真实请求体积、网络、内存和远距跳转仍待后续自动化浏览器验证。完整数据及复现方法见 [性能基准](PERFORMANCE_BASELINE.md)。

## D26 — 无账号的 Chromium 端到端测试与供应链门槛（阶段九）

采用 Playwright Chromium 持久浏览器上下文加载真实构建的 MV3 扩展；用固定 HTML/API 响应模拟 ChatGPT 而不连接正式页面与真实账户。对比仅使用 jsdom 的方案，这可以覆盖真实内容脚本注入、浏览器存储、设置同步和布局渲染，同时避免测试依赖 ChatGPT 登录与实时 DOM。代价是 CI 下载浏览器的时间和模拟结构的覆盖局限；真实 ChatGPT 页面与编辑历史仍需后续独立验收，不能标为通过。为保持现有锁文件和生产依赖稳定，Playwright 作为固定版本的 CI 临时测试工具在构建后安装；升级时需专门审查兼容性与许可证。保留只读 GitHub Actions 权限，CI 对包内 Manifest 权限、源 Manifest 权限、锁文件许可证及完整性字段进行审查，并通过 npm 公告库阻断高危已知依赖漏洞；审查输出必须留档且不能视为零漏洞承诺。回退：移除新 CI 步骤和测试脚本的阶段提交，恢复原有 Vitest 与构建检查，扩展产物格式与用户数据不变。


## D27 — Shared serial queue for all current local-data mutations

Stage 10 introduces one rejection-safe queue in the Manifest V3 background worker. Prompt list commits, TOC alias commits, usage counters, theme/sidebar preferences, and backup export/restore all use the same queue. Prompt usage reconciliation reads the latest persisted prompt list rather than trusting a stale tab-local list. Backup restore estimates post-restore storage usage before the first write and rejects over-quota restores. This avoids interleaving among current extension write paths but is not a Chrome Storage transaction; old-version scripts and any future direct writers can bypass it. Rollback remains compensating rather than atomic.

## D28 — Keep CI verification separate from publication and protect main administratively

CI uses supported GitHub Actions major versions and checks that the deprecated v4 action family is not reintroduced. CI remains read-only and does not publish. Repository branch protection was initially inactive and could not be changed through the available GitHub connector. On 2026-10-24 the administrator activated Ruleset 25771265 for `main`; GitHub confirms its active enforcement, required PR, strict two-job CI checks, blocked force push/deletion and no bypass. This closes the merge-governance blocker without changing application permissions or release policy.

## D29 — 不可信网页删除通知不得清除扩展本地数据（阶段十临时决定，后由 D30 扩展）

阶段十发现 MAIN world 向 ISOLATED world 发布的 `TOC_CONVERSATION_DELETED` 事件可以被同源网页脚本伪造。仅凭 `event.source`、`origin`、会话 ID 和网页可访问的令牌，都不足以证明该事件来自成功的真实删除操作。

阶段十采用**保守、不破坏数据的临时方案**：忽略 `window.postMessage` 删除通知，避免页面伪造成功 DELETE 清空持久别名。该方案在 D36 被替代：继续忽略页面消息作为授权，但由扩展后台的浏览器网络层独立观察真实删除请求，并只在成功响应后发送可信 runtime 通知。

**已知功能取舍**：真正从 ChatGPT 删除的会话，其旧本地目录别名及相关缓存不会因为页面通知被清理，可能保存在浏览器本地及用户导出的备份中。这些本地记录既不会自动上传，也不代表会话仍存在于 ChatGPT 服务器。用户仍能对可见会话撤销单条目录别名；针对已删除会话的可信独立确认或显式清理界面须作为单独后续需求设计与验收。在此之前，宁可保留陈旧本地文字，也不相信无法认证的页面通知。

回退：若需恢复自动清理，必须先实现可靠的扩展侧验证或用户明确授权的持久清理，并补充安全回归测试；不可仅通过重新接通 `postMessage` 的删除路径回退。


## D30 — 用隔离环境同源请求确认账号，不信任页面身份消息（阶段十一）

备选方案 A：继续在 MAIN world 读取 session 后经 `window.postMessage` 转发到 ISOLATED world。该方案无法阻止同源页面脚本伪造账号信息。备选方案 B：由扩展隔离环境直接向当前 ChatGPT 站点的 `/api/auth/session` 发起携带同源登录状态的请求，再验证 `user.id`。选择 B：账号信息不再通过网页可伪造消息设定，切换会话或窗口重新获得最新验证结果，晚到请求不能覆盖新结果。不同账号、未验证状态或旧数据 `ownerId=null` 不展示本地目录别名，原记录仍保留在存储与备份中，避免不可逆迁移和数据误归属。该方案增加同源账号查询，实际登录站点的请求可用性尚未验收；若旧无归属别名需要重新绑定，必须另设显式用户确认与可信归属证明。该限制不等价于浏览器配置文件内的加密或完全多账号访问隔离。

## D31 — 备份消息 ID 必须满足日常存储的同一校验（阶段十一）

备选方案 A：备份导入单独保持较宽松的 `text` 检验，允许用户通过 JSON 恢复不能进行后续编辑的目录 ID。方案 B：两路径共享同一消息 ID 验证谓词，并在写入前拒绝保留对象字段。采用 B，避免恢复成功却在普通存储读取中失败。会话路由 ID 与消息 ID 仍为不同校验范围，不能把所有 `__proto__` 路由无差别禁用导致旧格式不兼容。

## D32 — 批量清空采用单后台操作与补偿回滚（阶段十一）

备选方案 A：UI 继续分别提交提示词列表清空和使用统计清空，即使两者都排队也可能穿插备份及使用记录写入。方案 B：后台队列中校验用户确认时读取的提示词快照，对提示词和使用统计发起同一 `chrome.storage.local.set`，读取核验后确认成功；异常时恢复旧值且核验回滚。采用 B，并拒绝迟到的使用次数增加对已不存在 ID 的写入。Chrome Storage 不保证系统级跨键事务，持续故障或旧版本绕过协议时补偿也可能失败，因此用户仍需要离线 JSON 备份；失败 UI 必须显示真实错误，不得无条件宣称“未清空”。

## D33 — 阶段十一按新版本规则验收，不开展旧版无归属目录别名迁移（2026-10-24）

**用户确认的产品事实与范围：** 当前不存在老用户。第一阶段按新版本的账号归属机制交付，不要求恢复或迁移历史 `ownerId=null` 的目录别名，也不为此增加额外配置界面或自动认领逻辑。本决定解除阶段十一原先专门针对旧用户升级兼容性的待验收项。

**实际行为：** 新增和编辑自定义目录标题要求可信 ChatGPT 账号标识；同账号的别名可以显示和编辑，其他账号、无法验证账号和没有归属信息的别名不展示。对 `ownerId=null` 且已存在内容的本地记录仍拒绝未经证明的归属接管。防御性保留这些记录不等于承诺旧版本数据迁移；不自动删除、不重写、不根据网页消息断言归属。保留通用 JSON 备份与恢复行为及验证规则。

**验收及回退：** 以第一阶段的账号伪造、跨账号隔离、备份校验和批量清空自动化测试，以及最新分支 CI 为验收依据；旧用户无归属数据迁移测试不属于当前交付范围。真实已登录 ChatGPT 环境、旧新版本混合标签页仍属未验证环境，不得称已通过。若日后实际存在历史数据恢复需求，须重新立项，设计有可靠归属证明的显式迁移，不绕过隔离或直接覆盖旧记录。此范围决策不是合并 `main` 或发布版本的授权。

## D34 — 单标签页使用模式下移除跨标签页冲突协议（2026-10-24）

用户明确限定一次只操作一个 ChatGPT 标签页。方案 A 保留提示词快照 CAS、目录别名逐条旧值比对、侧边栏设置字段条件写入和自动冲突重试；功能不需要但增加维护成本。方案 B 删除这些跨标签页专用冲突判断，保留单上下文保存顺序、后台备份恢复串行、格式和权限校验、清空回滚以及失败提示。本次选择 B。

本决定取代 D21、D22 关于跨标签页条件写入的当前实现说明；D27 的共享队列继续保证同一扩展后台的备份恢复和异步写入顺序，D32 的清空回滚仍有效，但不再验证确认时的旧提示词快照。多标签页同时保存相同记录时可能静默覆盖，因此不属于支持场景。原有 Chrome 本地存储键和记录格式保持不变，无须迁移。真实浏览器使用仍需验收；通过回退本阶段提交可恢复旧逻辑。


## D35 — 提示词与目录别名必须绑定账号，备份保留偏好设置（2026-10-24）

新版本不再保留无账号归属的提示词或目录别名：后台在共享写入队列中清理提示词列表里缺少 `ownerId` 的记录及其孤立使用统计，并清理目录别名中缺少账号归属的记录；不把旧记录自动绑定给当前账号。提示词列表按当前可信账号过滤，同一账号的提示词跨对话共享；编辑和清空只作用于当前账号，其他账号的数据及使用统计必须保留。目录别名必须具有有效 `ownerId`，并继续按会话 ID 保存，未知账号时不显示、不写入。

完整 JSON 备份版本升级到 2，提示词和别名都必须携带账号归属；导入时拒绝未绑定记录及同 ID 跨账号冲突。主题和侧边栏偏好继续包含在备份和恢复流程中。普通编辑不再做跨标签页旧值冲突比较，但提示词/别名输入校验、共享后台写入队列、批量清空回滚、备份容量预检和恢复回滚保留。移除无调用方的提示词整表保存接口及侧边栏全量写入分支。

**删除会话的限制**：页面 `postMessage` 不能单独授权删除本地数据。当前使用 D36 的后台 `webRequest` 观察器确认成功的真实删除类网络请求；若请求未被观察、发生重定向、返回非 2xx 或账号无法重新验证，自动清理将保守地跳过，用户仍可通过设置页的本地清理流程处理残留记录。


## D30 — 通过浏览器网络层确认真实会话删除（2026-10-24）

同源网页可以伪造 MAIN-world `postMessage`，而 GET 404/410 也可能来自不支持的接口或访问限制，因此这两种信号都不能授权清理本地别名。为满足自动清理真实删除会话的需求，扩展在 MV3 service worker 中注册非阻塞 `chrome.webRequest` 观察器，过滤范围仅限 `chatgpt.com` 与 `chat.openai.com` 的会话 API 路径；只识别顶层 `DELETE` 或明确的非归档 `PATCH is_visible=false`，并仅在同一 requestId 完成且状态码为 2xx 时通知发起请求的标签页。隔离世界通过 `chrome.runtime` 接收通知，重新验证会话账号与已有别名归属，再调用原有带持久删除围栏的串行写入流程。

代价是新增 `webRequest` 权限及仅限两个 ChatGPT 站点的主机权限。观察器不阻止或改写请求，不持久化请求正文，不记录消息内容，也不发送到外部服务；PATCH 正文只在内存中解析 `is_visible` 和 `is_archived` 字段。审计测试将精确允许这两个权限和站点范围，同时继续拒绝 `webRequestBlocking`、额外权限和广泛主机范围。若 Chrome 或 ChatGPT 改变网络 API，自动清理会失败关闭，保留数据并继续提供用户确认的本地清理。
